Imported 2026-11-16 on the private feature branch `vortex-chain-nov-20261116` (not merged to main).
These are HOL Light proofs, run through hol-hearth's Wasm model, about the exact bytes of
`tasks/bubble-echo/vortex/purist/vortex_a1.wasm` (sha256 `a3cf8c82...6aede6`), the November "purist" module.
They do **not** prove the v5.8/Harvard renderer, the browser page, the GPU tracers or the physics.
The October v1 engine results (`ve_core.wasm`, PRs #72/#76) are separate rows and are unchanged.

## Start here

- The claims: `../evidence/vortex_evidence.json`, key `chain_nov`. It has one row per result (C1, C2, C3a, C3b, C4, C5,
  C5', C6a, C6b, C7a, C7b, C8b, C8a-births, C8a-tick, C8p-P12/P34/P5/P67, C8e, C8f-pop/auto/click/pair). Tick,
  routine, film and endpoint claims are kept as separate rows. C8f is one receipt (`c8f_final`) split into four rows (the
  C2 pop window, the auto film, the click film and the click pair); each of them names the spec theorems it claims in
  `claim_theorems`, and the row is PROVED only if every named theorem is a matched, proved binding (`row_problems` empty).
  Nothing is pending. Each row's `title` is only a short
  label: the full reviewed wording with every premise is in the row's `class_sentence`. A receipt counts as PROVED only
  when `problems` is empty. The file is generated by
  `../evidence/gen_ve_evidence.py`, and the rows come from `../evidence/va1_chain.py`. Read that file's docstring for
  the exact PROVED conditions.
- The authoritative wording of each result, including what is **not** proved, is its reviewed class sentence in
  `class/`. Each row also copies the "Not proved / Not covered" part of that sentence.
- The lane view is `lanes/vortex-echo-v1/lane.json`, receipt set `vortex-chain-nov` (24 receipts). Its STATUS.md is
  rendered with `tools/vab lane render`.

## Layout

| path | what |
|---|---|
| `../proofs/chain_*.ml`, `c8*.ml`, `pop_*.ml`, `va1_*.ml`, ... + `*.spec` | proof sources and frozen specs, at the same relative paths as in the proving trees (`tasks/bubble-echo/vortex/proofs/`) |
| `../purist/vortex_a1.wasm` | the module the theorems are about |
| `overlay/tasks/bubble-echo/vortex/proofs/` | November copies of 7 October `ve_*` files. They differ from main only in being retargeted from the 2 MiB `ve_core.wasm` memory to the 4 MiB `vortex_a1.wasm` memory, plus `ve_vk.ml` naming its split `ve_vk_g*` parts. main keeps the October files, because the October receipts name them |
| `evidence/receipts/<case>.attest.json` | `hearth attest --json` of each official receipt (+ `.inspect.txt`, and `.cold.json` where a cold replay exists) |
| `evidence/closures/<case>.closure.json` | each receipt's own closure inventory (`source_dependency_closure` from its transcript): its `strict_sha256` recomputes (sha256 of the sorted compact JSON) to the attest's closure sha256, and its files are exactly the attest's |
| `evidence/check-rung/<case>.check-rung.{cmd,out}` | `~/lanes/bin/check-rung` (receipt, spec lock, freeze record, mutants). C1/C2 predate the tool |
| `evidence/RUNS.tsv` | official run directory of every case (bluestar26 provenance) |
| `recipe/finish-c8-stages.json` | the layered proving order of the finish-c8 tree (45 stages: 35 stage leaves + the 9 C8 finals + the C8f final), each with its basis parent and flag (`--basis-parent`, or `--basis` for the C8f final), official run, receipt sha256, verdict line and the closure files it read (all in the tree or overlay); the stage leaves are imported under `../proofs/` |
| `frozen/FROZEN-*.txt` | spec freeze records: spec sha256, time, Sol review id and score |
| `class/*.txt` | the reviewed class sentences; `C8f-r2.txt` and `C8b-r2.txt` are the corrected versions (2026-11-17) |

Host paths inside the attest files (bluestar26 `/home/bluestar/lanes/demo1-wave-20261110-141705/...`) are provenance.
They are not inputs. Every closure file a receipt read under its proving tree is in this repository with the recorded
sha256, either at its natural path or in `overlay/`. The generator checks this (`closure_files_in_repo`).

## Reproduce

From a checkout of this branch:

```sh
# 1. regenerate and check the claim rows (stdlib only; any host)
python3 -I tasks/bubble-echo/vortex/evidence/gen_ve_evidence.py /tmp/ve.json && cmp /tmp/ve.json tasks/bubble-echo/vortex/evidence/vortex_evidence.json
python3 -m unittest discover -v -s tasks/bubble-echo/vortex/tests -p 'test_chain_nov.py'
tools/vab lane check lanes/vortex-echo-v1/lane.json

# 2. the exact November proving tree: a scratch worktree with the overlay applied
git worktree add /tmp/vortex-nov HEAD
cp -R tasks/bubble-echo/vortex/chain-nov/overlay/. /tmp/vortex-nov/
# then, on a Linux host with hol-hearth at the recorded controller (Hearth refuses to run on the Mac), from /tmp/vortex-nov:
#   C1..C7b and C8b: every basis layer in their attests has selection "automatic" (made by `hearth prove` itself), so
#     hearth prove tasks/bubble-echo/vortex/proofs/<case>.ml --profile wasm --spec tasks/bubble-echo/vortex/proofs/<spec>.spec
#   (deep ones may need a long --prep-timeout);
#   C8a/C8p/C8e/C8f (layered): walk recipe/finish-c8-stages.json in order; for each stage
#     hearth prove <leaf> --profile wasm [--spec <spec>] [<basis_flag> <the .automatic dir the parent stage's receipt
#       names in project_basis.identity.source>] --timeout <900 for a stage leaf, 1800 for a C8 final (2400 for c8a_birth_final),
#       1500 for the C8f stage and final> --prep-timeout 2400
#   (what the finish-c8 and finish-c8f drivers did; these layers have selection "explicit").
#   The C8f final passes --basis (the c8fst stage's own layer), not --basis-parent.
# Use plain --spec, not --benchmark (see the freeze records). These commands are documented from the records and
# statically checked (test_chain_nov: every stage leaf and closure file present, parents in order); they were not
# re-run from this checkout.
# A cold replay of an imported receipt: the attest's `reproduce.cold_check` command (needs the original run dir).
```
